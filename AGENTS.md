# Правила проекта Редстар

## Публикация кейсов

Каждый новый кейс обязательно добавлять в оба списка:

- `keysy.html` — отдельная страница «Кейсы».
- `zhurnal.html` — страница «Журнал», где кейсы публикуются вместе с остальными материалами.

Обновлять также соответствующие страницы в `glass/`, пока эта версия поддерживается в проекте.
Карточке задавать тег `keysy` и теги направлений, чтобы она попадала в нужные фильтры. На странице «Кейсы» должны оставаться только кейсы и фильтры по представленным направлениям; в журнале сохраняется общий набор рубрик.
Перед завершением публикации проверить наличие карточки и переход на страницу кейса в обоих списках.

В журнале (`zhurnal.html`, его копии в `glass/` и `_fragments/blog.html`) располагать карточки по дате публикации: от новых к старым. При добавлении материала сохранять этот порядок.

## Выкладка на сервер

Сайт живёт на облачном сервере 83.217.192.146 (Таймвеб). Сервер общий: на нём olegrodin.com,
архив BOOST, Telegram-бот и демо-поддомены. Вход — `ssh kapustina@83.217.192.146`, права через `sudo`.

- **Домены.** Основной — redstar.agency. Прежний redstaragency.ru целиком уводится 301 на redstar.agency
  (второй `server` в том же конфиге). Поддомены обоих доменов живут на других серверах — их DNS-записи
  не трогать. Почта `@redstaragency.ru` — на Яндексе: MX и TXT домена не трогать.
- **Выложить:** закоммитить и запустить из корня репозитория `bash deploy/deploy.sh` (на Windows — в Git Bash).
  Уезжает только закоммиченное. В конце скрипт печатает ответы сервера: страницы — `200 text/html`,
  старые адреса Тильды — `301`. Код 200 без правильного типа — не успех.
- **Откат:** `sudo rm -rf /var/www/redstar-agency && sudo mv /var/www/redstar-agency.old /var/www/redstar-agency`.
- **Новая страница** — добавить её в `sitemap.xml`. Переадресацию делать не meta refresh, а `return 301`
  в конфиге nginx.
- **Конфиг nginx.** Главная копия — на сервере, `/etc/nginx/sites-available/redstar.agency` (в ней строки
  certbot); `deploy/nginx/redstar.agency.conf` — её копия. Правка: бэкап в `/root/nginx-backups/`
  (не в `sites-enabled/` — nginx подхватит его как второй сайт), правка, `sudo nginx -t`, только потом
  `sudo systemctl reload nginx`, затем та же правка в копию в репозитории. Ошибка в любом конфиге при
  reload кладёт все сайты сервера.
- **Чужое не трогать:** конфиги других сайтов, `/var/www/*` кроме своих папок, бот `olegrodin-bot`,
  сертификаты других доменов.
- **Демо-поддомены** выкатывать закрытыми от индексации: в `server` после `index index.html;` —
  `add_header X-Robots-Tag "noindex, nofollow, noarchive, noimageindex" always;` и
  `location = /robots.txt { default_type text/plain; add_header X-Robots-Tag "noindex, nofollow, noarchive, noimageindex" always; return 200 "User-agent: *\nDisallow:\n"; }`.
  Сначала конфиг с noindex, потом `certbot`: имя поддомена попадает в открытые логи сертификатов, и поисковики
  находят его за часы. `add_header` внутри `location` отменяет заголовки уровня `server` — дублировать.
  Сам redstar.agency открыт для поиска, noindex на нём не ставить.

## Порядок согласования изменений

Сначала публиковать изменения только на GitHub Pages (ветка main). Не запускать deploy/deploy.sh и не менять боевой сервер без отдельного указания пользователя «публикуй на боевой».
Страницы uslugi-proverka-rkn.html и uslugi-obnovlenie-bitrix.html пока являются пустыми черновиками: noindex, nofollow, без включения в sitemap.xml. Добавить в sitemap и снять noindex только после наполнения и согласования публикации.

## Индексация тестовой версии

Во всех новых HTML-страницах добавлять в head `<meta name="robots" content="noindex, nofollow" data-preview-only="true">`. GitHub Pages публикует исходники, поэтому этот тег обязателен. Перед любой боевой публикацией (в том числе частичной) запускать `deploy/public_links.py` для файлов релиза: он удаляет только тег с `data-preview-only`, сохраняя остальные запреты. Не закрывать robots.txt от обхода: робот должен прочитать noindex.
