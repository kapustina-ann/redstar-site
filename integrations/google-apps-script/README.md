# Подключение заявок Редстар

Сайт остаётся на GitHub Pages. Обработчик размещается в Google Apps Script.
Таблица: https://docs.google.com/spreadsheets/d/1R_l94R9Qu84GR18RoVctYjZt0dSp9kTFhKioUBzFFV0/edit
Бот: @redstaragency_leads_bot. Группа: «Редстар — продажи».

## Настройка владельцем Google-аккаунта

1. В таблице откройте **Расширения → Apps Script**.
2. Замените весь исходный текст файла `Код.gs` / `Code.gs` содержимым файла `Code.gs` из этой папки. Сохраните.
3. Откройте **Настройки проекта** (шестерёнка) → **Свойства скрипта** → **Добавить свойство скрипта**.
   Имя: `TELEGRAM_BOT_TOKEN`. Значение: токен, полученный от BotFather. Сохраните. Не вставляйте токен в исходный код или GitHub.
4. Убедитесь, что бот добавлен в нужную группу и может писать в неё. В группе отправьте `/start@redstaragency_leads_bot`.
5. Вернитесь в редактор. Выберите функцию **setup** в списке сверху и нажмите **Выполнить**. Разрешите своему скрипту доступ к таблице, внешним запросам и триггерам.
   Функция определит ID группы, сохранит его в свойстве `TELEGRAM_CHAT_ID`, создаст отдельный лист **Заявки сайта** и триггер повторной отправки раз в 5 минут.
   Исходные листы не изменяются. Если группа не найдена, проверьте точное название, повторите команду в группе и запустите setup снова.
6. **Развернуть → Новое развертывание → Веб-приложение**. Выполнять от вашего имени. Доступ: **Все** (включая пользователей без входа в Google).
7. Скопируйте URL развертывания, который заканчивается на `/exec`, и передайте разработчику. Это публичный адрес приёма заявок, его можно прислать в чат.
8. Разработчик указывает URL в `assets/leads-config.js`, повышает версию подключения конфигурации на всех страницах и публикует сайт.
9. Выполните одну тестовую заявку. Проверьте строку в таблице и сообщение в группе. Проверьте отдельные источники: главный баннер → контакты, кнопка на услуге → форма и заполнение без кнопки.

## Данные и доставка

Каждая заявка содержит имя, телефон, задачу, дату по Москве, оба согласия, страницу формы, страницу перехода, блок и текст кнопки, ID формы, UTM и ID заявки.
Переход хранит только служебный контекст в sessionStorage, без имени, телефона или задачи. Он используется только на целевой странице в течение 30 минут.
Источник без нажатия кнопки обозначается явно. Для перехода в новую вкладку передача контекста зависит от копирования sessionStorage браузером; обычные кнопки открываются в текущей вкладке.

Сначала сохраняется строка в таблицу. Успешный ответ клиенту означает сохранённую заявку; уведомление Telegram может находиться в очереди. Повторная отправка неизменённой заявки из той же формы использует прежний ID и не создаёт вторую строку.
При ошибке данные не стираются, ложное подтверждение не показывается. Статус Telegram виден в таблице. Триггер повторяет до 10 ожидающих уведомлений за запуск. При неоднозначном сетевом ответе Telegram возможно повторное уведомление с тем же ID.

Не меняйте порядок и названия технических колонок листа «Заявки сайта». Для анализа создавайте отдельные листы. При изменении кода Apps Script обновляйте развертывание новой версией, а не только сохраняйте редактор.

Встроены проверка полей и согласий, экранирование формул для таблицы, скрытое поле-ловушка и лимит всплесков по телефону. Это базовая защита: публичный обработчик не аутентифицирует посетителей, а значения источника получены от клиента. При целевом спаме потребуется CAPTCHA или сервер с дополнительной защитой. Действуют квоты Google Apps Script.

## Разработка

`assets/leads.js` подключён ко всем основным страницам и зеркалам `glass/`. Пока `REDSTAR_LEADS_ENDPOINT` пуст, прежняя доставка остаётся без изменений. После настройки единый обработчик перехватывает обычные формы и Tilda-формы, чтобы исключить отправку через два транспорта.

Тесты: `node tests/leads.test.cjs`. Браузерные запросы подменяются: реальные заявки и сообщения не отправляются. Сквозная проверка рабочего развертывания обязательна после настройки.

Документация: https://developers.google.com/apps-script/guides/web и https://core.telegram.org/bots/api
